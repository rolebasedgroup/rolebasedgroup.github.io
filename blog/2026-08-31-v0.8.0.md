## 版本总结

v0.8.0 通过节点预热、原地调度和重启退避，减少推理服务启动与故障恢复中的重复开销，并修复扩缩容、滚动更新和升级兼容性问题。

升级前须[迁移 Helm 自定义配置](https://github.com/sgl-project/rbg/blob/v0.8.0/deploy/helm/rbgs/README.md#breaking-change-values-regrouped-in-chart-v080)，旧配置会被忽略；[CRD 升级工具](https://github.com/sgl-project/rbg/pull/437)的 kubectl 已更新为 v1.37.0，旧集群需[核对版本兼容性](https://kubernetes.io/releases/version-skew-policy/#kubectl)。服务发现及 alpha 升级提醒见下文。

## 新特性

### 节点预热：提前准备镜像与运行环境

新增 RoleBasedGroupWarmup，可在指定节点或已有 RBG 所在节点预拉取镜像、执行自定义预热任务，为后续部署或升级准备资源。任务支持并发控制、失败重试和超时限制，便于批量管理预热过程。

### 原地调度：让重建的 Pod 复用节点缓存

启用原地调度后，重建的 Pod 可优先回到同一工作负载运行过的节点，复用已有镜像和模型缓存，减少重复准备资源的开销。

若选择强制回到历史节点，节点不可用时可能无法完成调度，使用前请了解[适用条件与限制](https://github.com/sgl-project/rbg/blob/v0.8.0/doc/best-practice/zh/04-configuring-inplace-update-and-scheduling-policies.md)。

### 重启退避：减少连续故障引发的反复重建

对启用故障联动重建的角色实例，连续故障后的重建会逐步延后，避免短时间内反复重建整组 Pod。首次故障仍立即处理，后续重试间隔可按业务需要调整。

已有工作负载使用该重启策略时，也会默认启用退避；如需保持每次立即重建，可按[故障处理文档](https://github.com/sgl-project/rbg/blob/v0.8.0/doc/features/failure-handling.md#disabling-backoff)关闭。

### 其他功能增强

- **更早发现配置错误**：提交时即可拦截不合法的 RBG 名称、重复组件名及与 ScalingAdapter 不一致的手工副本修改，已有重名组件需在更新前修正。
- **按需收紧控制器权限**：新安装可禁用旧工作负载类型并移除相应权限，已有安装应保留默认兼容设置，详见[使用限制](https://github.com/sgl-project/rbg/blob/v0.8.0/deploy/helm/rbgs/README.md#deprecated-workload-types)。
- **更清晰的审计信息**：各控制器的 API 请求带有独立标识，方便在 Kubernetes 审计日志中追踪请求来源。
- **Model Express 集成示例**：Dynamo SGLang 示例补充模型分发服务的接入说明，方便在 RBG 部署中配置模型分发加速。

## 重大 bug 修复

### 保持 v0.7.0 存量对象可读取

修复重启策略格式变化导致旧对象无法读取、控制器无法正常同步的问题。从 v0.7.0 升级无需改写已有重启策略。

曾部署 v0.8.0-alpha.3 或 alpha.4 的用户，须按[升级说明](https://github.com/sgl-project/rbg/blob/v0.8.0/doc/features/failure-handling.md#upgrading)删除并重建受影响的 RBG 及关联资源，需安排可接受工作负载重建的维护窗口。

相关 PR：
- [#424](https://github.com/sgl-project/rbg/pull/424) — fix: restore restartPolicy as a string to keep v0.7.0 objects decodable

贡献者：
- [@diw-zw](https://github.com/diw-zw)

### 避免配置未变却触发滚动更新

修复控制器升级后，业务配置没有变化却触发滚动更新的问题，减少不必要的 Pod 重建与模型重新加载。

相关 PR：
- [#433](https://github.com/sgl-project/rbg/pull/433) — fix: add semantic revision equality check to prevent spurious rollouts
- [#439](https://github.com/sgl-project/rbg/pull/439) — Fix/upgrade spurious rollout and identity labels

贡献者：
- [@diw-zw](https://github.com/diw-zw)

### 防止配置更新引发意外缩容

角色副本数由已绑定的 ScalingAdapter 管理时，Helm 升级或外部配置更新曾可能让副本数意外回落。本版保持实际工作负载与扩缩容目标一致，避免因此引发 Pod 缩减。

相关 PR：
- [#306](https://github.com/sgl-project/rbg/pull/306) — fix(rbg-controller): override role.Replicas from bound RBGSA

- [@sebest](https://github.com/sebest)

### 修复单副本角色协同更新停滞

修复单副本角色在均未就绪时，受协同滚动更新进度约束而无法开始更新的问题，让这类部署能够继续推进版本变更。

### 修复小副本数更新与缩容到零被拦截

修正百分比更新策略在小副本数场景下的校验，避免合法的滚动更新被拒绝；同时修复使用百分比不可用额度时，角色无法缩容到零的问题。

### 让更新方式与宽限期按配置生效

修复原地更新宽限期未生效、部分更新路径未遵循指定策略的问题，让工作负载按配置选择原地更新或重建，并在原地更新前保留设定的等待时间。

### 补齐 worker Pod 的 DNS 身份

修复 RoleInstanceSet 的 leader-worker 角色在共享 Service 选择全部 Pod 时，worker 缺少独立 DNS 名称的问题，让依赖 Pod 域名的组件能够发现 worker。

升级提醒：未指定选择范围时，现在默认仅暴露 leader；依赖 worker 服务发现的用户须显式选择 `All`。已有显式 `All` 配置也会因本次修复触发 worker 重建，请按[升级说明](https://github.com/sgl-project/rbg/blob/v0.8.0/keps/260-leaderonly-service/README.md#upgrade-considerations)安排变更窗口。
