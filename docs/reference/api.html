API Reference

This document describes the API fields for RoleBasedGroup and related CRDs in workloads.x-k8s.io/v1alpha2.

CRD inventory​

KindAPI versionScopePurpose
RoleBasedGroupv1alpha2NamespacedUser-facing inference topology.
RoleBasedGroupSetv1alpha2NamespacedManage multiple RoleBasedGroups from one group template.
RoleInstanceSetv1alpha2NamespacedNative workload for one role.
RoleInstancev1alpha2NamespacedOne inference instance and its owned Pods.
RoleBasedGroupScalingAdapterv1alpha2NamespacedHPA/KEDA/KPA scale target for one role.
CoordinatedPolicyv1alpha2NamespacedCross-role update and scaling policy.
ClusterEngineRuntimeProfilev1alpha2ClusterReusable runtime profile injected into role Pods.
RoleBasedGroupWarmupv1alpha2NamespacedPrewarm engine runtime before traffic.
Instance / InstanceSetv1alpha1NamespacedLegacy internal workload; use RoleInstance / RoleInstanceSet.

RoleInstanceSet and RoleInstance are the v1alpha2 workload primitives. InstanceSet is the legacy v1alpha1 spelling and is not part of the v1alpha2 surface.

InPlaceUpdateStrategy​

FieldDescription

RestartPolicyConfig​

Configured under spec.roles[].leaderWorkerPattern.restartPolicyConfig or spec.roles[].customComponentsPattern.restartPolicyConfig.

FieldDescription
typeRestartPolicyType — None or RecreateRoleInstanceOnPodRestart (default for multi-pod patterns)
activateAfterstring — Ready (default) or Created; controls when native RoleInstance restart triggers become active
baseDelaySeconds*int32 — base exponential backoff delay in seconds; minimum: 0, default: 30
maxDelaySeconds*int32 — maximum backoff delay in seconds; minimum: 0, must be >= baseDelaySeconds, default: 600
maxGroupRestarts*int32 — maximum automatic whole-instance rebuilds per RoleInstance and topology/Pod-template revision; minimum: 0, unset: unlimited. 0 stops recovery on the first eligible fault. Requires explicit type: RecreateRoleInstanceOnPodRestart; native RoleInstanceSet workloads only

activateAfter, backoff delays and maxGroupRestarts apply to native RoleInstanceSet workloads, not backing Deployment, StatefulSet or LeaderWorkerSet workloads.

Compatibility: These settings are v1alpha2-only. Writing a spec through v1alpha1 drops activation, backoff and budget settings; an omitted budget means unlimited recovery. Manage budgeted workloads through v1alpha2.

RoleInstance budget status​

FieldDescription
status.groupRestartCountint32 — accepted whole-instance rebuilds for the current budget revision; does not reset after Ready or a quiet period
status.groupRestartRevisionstring — opaque budget revision identifying component topology and Pod templates, including sizes
status.restartBudgetExhaustedbool — budget exhausted; automatic Pod creation and updates are suppressed until explicit recovery or a new topology/Pod-template revision

See Bounded Group Recovery for examples, exhaustion behavior, recovery and configuration-change semantics.

RestartPolicyType​

ValueDescription
NoneNo automatic restart
RecreateRoleInstanceOnPodRestartRecreate only the role instance

See Failure Handling for native RoleInstance activation, wave-scoped Restarting guard semantics, backend support and upgrade/rollout considerations.

ScalingAdapter​

FieldDescription
enablebool — enable autoscaling (default: false)

EngineRuntime​

FieldDescription
profileNamestring — ClusterEngineRuntimeProfile name (required)
componentstring — the one component of the role's pattern this reference operates on: leader or worker under leaderWorkerPattern, a declared component name under customComponentsPattern, the role's own name under standalonePattern (any other name there is a render error). Absent, the fragments (and the legacy containers merge) deliver to the pattern's default component set — the leader only under leaderWorkerPattern, every declared component under customComponentsPattern, the single role-named component under standalonePattern. Required whenever targetContainers is set, except under standalonePattern, where a component-less reference carrying targetContainers is scoped to the role's own name
targetContainers[]EngineRuntimeTargetContainer — one entry per container this reference touches: the entry's name is the consent to the profile's containerPatches at that container and the address of the entry's own extraPatches (requires component; duplicate names rejected at write time via the map list)
containers[]Container — legacy: role-provided env/args appended to profile-declared containers within the reference's component scope; superseded by targetContainers[].extraPatches
injectContainers[]string — inert: accepted and ignored, nothing reads it; removed at the next API version boundary

EngineRuntimeTargetContainer​

FieldDescription
namestring — the rendered container this entry addresses (required): role-declared or profile-declared, containers and init containers alike. Listing the name is the single toggle — it consents to the profile's patches at that container and fixes where the entry's extraPatches land. A name the role's own template also declares resolves to the role-owned container; a name injected only by a different reference or profile is a render error
extraPatches[]ContainerPatch — the role's RFC 6902 patch rules for this entry's container, applied in list order after the profile's containerPatches — all five roots at any index; what the role writes lands where it is written. Optional, 1–32 items

ClusterEngineRuntimeProfile​

FieldDescription
apiVersionworkloads.x-k8s.io/v1alpha2
kindClusterEngineRuntimeProfile
metadataStandard Kubernetes metadata (cluster-scoped)
specEngineRuntimeProfileSpec

EngineRuntimeProfileSpec​

FieldDescription
updateStrategyUpdateStrategy — NoUpdate or RollingUpdate. Deprecated: accepted and never consumed; immutability removes the surface it would have governed, and the field is removed at the next API version boundary alongside injectContainers (see Profile Mutability)
initContainers[]Container — init containers to inject
containers[]Container — sidecar containers to inject
volumes[]Volume — volumes to inject
containerPatches[]ContainerPatch — the profile-side patch list: target-less ordered entries, each firing at every targetContainers address a referencing engineRuntimes[] entry lists, in list order. Profile-side entries may address /env, /volumeMounts and /command/0 only; /args, /command/<i> with i > 0 and /securityContext/capabilities/add are role-side-only roots, and a profile-side entry addressing one is a render error attributed to the profile. Optional, 1–32 items. Mirrored into v1alpha1 with identical markers

EngineRuntimeProfileStatus​

Maintained by the controller as reference tracking (display and detection surface; rendering never consults it, and enforcement stays with the admission webhook):

FieldDescription
referenceCountint32 — the count of live references (RoleBasedGroups and RoleBasedGroupSet group templates), surfaced as a REFERENCES printer column
referencedGenerationint64 — the metadata.generation at which the profile became referenced, recorded on the none-to-referenced transition, never refreshed while referenced, cleared when the last reference leaves
conditions[]Condition — carries the Frozen condition: True with reason Referenced while referenced, flipping to reason SpecChangedWhileReferenced when metadata.generation no longer matches referencedGeneration (evidence the spec changed since the baseline was recorded: a bypassed write, or a legal edit in a zero-reference window the controller never observed)

ContainerPatch​

FieldDescription
jsonPatchContainerJSONPatch — the RFC 6902 format. Exactly one patch field must be set; today jsonPatch is the only one, and a future patch format joins as a sibling field

ContainerJSONPatch​

FieldDescription
opstring — patch operation; only add is accepted
pathstring — RFC 6901 pointer, relative to the target container. Must be an element pointer under /command, /args, /env, /volumeMounts or /securityContext/capabilities/add
valueobject — raw JSON matching the path's element shape: a string for /command, /args and capability elements; a corev1 EnvVar object for /env; a corev1 VolumeMount object for /volumeMounts

Ops apply in list order (later ops see earlier ops' mutations; add /command/0 head-inserts, so multi-element prepends are written in reverse). Same-named env entries resolve positionally, last-wins: a role-side append of an existing name is the override gesture; a profile-side entry for a name the target already carries must default ahead of it via /env/0, and a profile-side - append onto a role-owned name is a render error.

RoleInstanceSet Rollback Recovery​

status.rolloutReplacementState is managed by the controller during an early rollback (A → B → A). It preserves existing surge instances across controller restarts while base instances are being replaced.

FieldDescription
updateRevisionTarget revision of the replacements
replicasRecorded exclusive upper position bound when replacement intent was persisted
partitionRecorded inclusive lower position bound when replacement intent was persisted

When maxSurge is positive, the controller persists this state before replacing a base instance and waits for its cache to observe the write before reconciling again. It clears the state when all base members in the current update range exist, are ready at the target revision, are not terminating, and have observed their current generation.

The saved position bounds are not stable member identities: gap filling can move a different member into the same position. Completion therefore conservatively checks the entire current update range, without restricting it to the saved bounds. No additional API fields are required. Scale-up or a partition decrease may retain surge for newly eligible members, even after the original replacements recover.

A different target revision invalidates the previous state. An empty current update range ends protection; members outside that range no longer block it. Pause and resume preserve unfinished protection. After scale-down, a former base instance may temporarily act as surge until the current range is ready.

Update the RoleInstanceSet CRD together with the controller. If replacement intent cannot be persisted, the controller emits a Warning event and retries without replacing the instance; an outdated CRD may have pruned the new field. With maxSurge=0 there is no surge to protect, so replacement does not require this state and remains possible with the older CRD.
